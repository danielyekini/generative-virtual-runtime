# User steering protocol

Treat an explicit user change as current authority. Distinguish a question or
brainstorm from a committed direction change; ask only if the ambiguity changes
dependent work materially. An ordinary agent immediately pauses incompatible
commitments and routes to its owning orchestrator persona within the session.

Record the user's exact change or faithful bounded summary, affected goals/items,
what it supersedes and what remains unchanged. Update the charter only when the
vision/strategic boundary changes; otherwise update own direction/roadmap and
GitHub priorities, acceptance and dependencies. Notify the other orchestrator
through its request inbox. If it changes a shared contract, mark the affected
items pending agreement; continue independent authorised work.

Do not cancel unrelated in-flight work or overwrite historical results. Record
why paused work was paused. Preserve prototypes and close/defer superseded issues
with links. Produce a concise 'effective next run' summary. Steering does not
require the user to supply internal issue IDs, branches or document paths.
