## Current dependency direction

Engine: assembled-scene delta correctness -> persistent entity/edit/behaviour
design + bounded critique -> implementation -> dependencies/instances/expressive
authoring. Keep ongoing capacity work evidence-driven; do not reopen cloning/index
work already resolved in PR #11. Design interaction/audio/spatial ownership early.
**Immediate (2 November 2026):** generative audio via ElevenLabs (E031 design)
is P0 engine work for M4; do not hard-wire vendor APIs into Scene IR.

Product: bounded Studio workflow alternatives -> implement library/editor/
execution/fullscreen slice -> truthful streaming inspector -> **Studio testing
surfaces for interactions and native generation (human quality judgment;
director distillation)** -> speech/audiovisual host paths -> customer teaching
workflows. Every product run prioritises actionable Engine→Product requests that
assist verification. Animation quality dominates generation acceptance; latency
and failure rate are secondary optimisations.

These are coordinated lanes, not a single waterfall. Product can start on Studio
while engine repairs delta validation. Design contracts early where lanes meet;
do not block useful work on a speculative universal design.

## Ready-work and research policy

Each orchestrator maintains its own ordered Ready queue in GitHub, normally at
least two independent tasks or explicitly justified blockers. Research items
name the decision they unlock, alternatives, budget, evidence and stopping rule.
After two non-improving attempts choose a materially different approach, narrow
the scope or stop; renaming the approach does not reset its history.
Future ideas enter Candidate, get evaluated and promoted/deferred/rejected by
the owning orchestrator. Frequency in an audit is evidence, not an automatic priority.
