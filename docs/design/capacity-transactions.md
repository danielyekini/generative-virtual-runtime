# Practical capacity: transactions, graph resolution and progressive units

Decision 2026-10-30. Scope: compatible implementation changes under MotionScript / Scene IR 0.5.0, wire 0.2. Evidence: [capacity run](../evaluations/2026-10-30-capacity/report.md). No new syntax, persistent entities, interactions or renderer semantics.

## Compiler transaction requirement

Accept or reject one dependency-complete unit atomically, including batches, without rewriting sealed history. Preserve all reference/capability, writer-conflict, timing, geometry and resource checks and their diagnostics.

Lowering appends list entries or replaces list containers; it does not edit accepted nodes, geometry, keyframes, resources, scopes or definitions in place. A transaction therefore copies **list containers**, not their nested values. Constants and scalar counters/frozen/sealed state are checkpointed too. Rejection restores those containers/state; diagnostic provenance survives. Nested batches own independent checkpoints. Children do not emit deltas until their enclosing batch succeeds.

Alternatives: deep clones retained the same validation but copied megabytes of old morph geometry for every subsequent unit; mutation journals would avoid list copies but require more invasive auditing; persistent collection libraries add API/ownership complexity. Shallow containers are the smallest effective change. Full scene validation remains on every accepted candidate and at finalisation. The validator shares a node lookup across depth checks within each node list; every node and every other check is still visited. No validation result survives the call. Delta validation was deliberately deferred because dependency-invalid intermediate prefixes and preserved diagnostic attribution need a larger proof than this milestone.

Streaming boundaries, deferred dependency resolution, deltas and seals are unchanged. Counter/frozen rollback now covers a failed batch that included a seal. Visibility steps before a seal are rejected with source spans, matching the existing track guard and sealed-history requirement; boundary-time steps remain permitted. This closes an implementation hole, rather than changing the published seal meaning. Cancellation takes effect between incremental pushes; complete-file calls remain synchronous. Snapshot retention is O(container entries) per active nested transaction, with geometry shared. Revisit before adding any in-place revision/edit operation; such an operation must replace an immutable value or extend the transaction journal. Do not mutate a previously accepted nested object.

## Sample-local graph requirement

Preserve containment ordering, stable zIndex ties, independent transform-parent chains, screen/world root selection, visibility, isolated ancestor opacity exclusions and the skip-exactly-one opacity rule. Deterministic seeking must not depend on previous samples.

Frame construction builds one ID lookup and sorted child buckets for the sample. One containment traversal resolves hidden/screen state and draw order. Transform matrices are memoized only within this sample; camera view is calculated once. Opacity walks share the ID lookup and preserve original multiplication order. Render-tree and flat routes use the same sorted child buckets. No sampled value or graph cache is retained across evaluations.

Alternatives: persistent revision-keyed topology indexes can save another O(N) pass, but would require new invalidation ownership in complete, streaming and presentation paths. The measured gain from eliminating repeated per-drawable indexes is already large. Sample-local ownership is intentionally simpler: additions, revisions, cancellation, scene replacement and disposal cannot expose an old entry. Geometry/track payloads and all sampled poses retain their existing ownership. Revisit persistent indexes only if another profile proves this remaining O(N) construction material. Drivers, bindings and later interactions will require separate dependency graphs and revision/ownership rules; this is no implicit support for them.

## Admission requirement and decision

`maxNodes` bounds the **total assembled scene**, including composition definitions; it is not a per-frame scheduling allowance or a guarantee of 60 Hz. The original 500 is labelled a prototype budget in `limits.ts`; its exact historical numeric rationale is **unknown**. Finite rejection remains necessary to bound validation, retained scene state, traversal and renderer work.

Raise the live default to **2,000 nodes**. Existing adapters already use a 2,000-node validation profile. Controlled browser experiments at 250/500/1,000/2,000/4,000 primitive nodes found 2,000 affordable on the measured machine; 4,000 exposes renderer submission and tail latency, so that remains an explicit non-default experiment. Full scene admission and queue rejection remain finite. Configurable `validateSceneIR` overrides continue to serve scoped experiments. This does not retroactively change historical fidelity profiles/quarantines or publish language releases. Revisit on target devices, richer node/resource combinations, or a measured requirement beyond 2,000.

Keep 1,000 tracks, 10,000 geometry items, depth 16, expression budgets, 4 MiB source, 1 MiB buffered unit and 256 runtime deltas. These bound different dimensions; no obstructing representative story justifies raising all dimensions together. Track/morph scaling results identify their costs separately. Original exact numeric rationale for prototype track/depth/geometry settings is unknown; their bounded-work purpose remains relevant. Audio, physics and 3D will need resource-specific budgets, not automatic multiplication of these values.

## Progressive authoring requirement and decision

Demonstrate meaningful motion while source continues arriving, using current predeclared objects, time-local writers and seals. Preserve the original story bytes as the comparison baseline.

The experimental *A Circle in Motion* variant predeclares all objects and operators (about 8 KiB), then partitions existing keyframe tracks only at **original key boundaries**, preserving whole segment easing. Each interval contains every writer/step necessary before its seal. Crossing segments arrive with the earlier interval; later writers never begin before the already sealed frontier. Initial writers, even long holds, are sent before the first seal. Subsequent intervals add motion/visibility, not objects. This uses current semantics; it neither permits new base definitions after the first seal nor introduces persistent editing. The variant grows from 42,008 to 61,505 UTF-8 bytes: duplicated boundary values and local timing are an explicit bandwidth/latency trade-off. It is an experimental authoring example, not a general optimiser or a canonical verified corpus promotion.

The old Studio/legacy demonstration feeds a fixed number of characters from each tick and deliberately pauses at starvation. That is useful for exercising its UI but cannot measure independent arrival throughput. The new runnable benchmark/example uses a Worker with absolute byte-arrival deadlines, independently of RAF. UTF-8 decoding spans fragmented bytes. Producer in-flight data is bounded to 256 fragments / 64 KiB, with acknowledgements and explicit overflow failure; rendering cannot silently lower the configured generation rate. Delivery lag and configured/observed rates are distinct. Compiler/runtime queues retain their existing bounded telemetry. No dashboard or actual model-generation speed claim is introduced.

The host visibly holds on starvation/truncation, reports rejection while keeping accepted history and stops the Worker and owned compiler/runtime on cancellation. Revisit a base-definition semantic change only when predeclared topology is an evidenced obstacle for the selected product goal. Arbitrary object creation during playback, conversational edits, ownership and interaction events remain future design work.
