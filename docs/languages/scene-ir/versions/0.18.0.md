# Scene IR 0.18.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0 for a new capability contract. Documents still declare `irVersion` `"0.2"` and gate the new feature with `requiredCapabilities` containing `text.dynamicContent`. A package that does not enable that capability rejects the scene at accept time; older validators reject the unknown `numeric` key on text nodes, content steps, and the `text.number` / `content` channels. Decision: `docs/decisions/engine/dynamic-text-and-metrics.md` (E013); landed by E040.

## Capabilities introduced

- text.dynamicContent

## Representation

Optional field on text nodes:

```ts
interface TextNumericFormat {
  fractionDigits?: number;
  minIntegerDigits?: number;
  sign?: "auto" | "always" | "never";
  group?: string;
  decimal?: string;
  prefix?: string;
  suffix?: string;
}

interface TextNumericContent {
  value: number;
  format?: TextNumericFormat;
}

// on TextNode:
numeric?: TextNumericContent;
```

- A non-empty `numeric` on any text node requires `text.dynamicContent`.
- New node track channel `text.number` (`NodeAnimChannel`, DSL path `number`, number) samples over the binding's base `value`. Legal only on a text node that has `numeric` (`INVALID_TRACK_TARGET`).
- Steps may target `content` with a single-line string value (in addition to `visible` / boolean). Content steps require `text.dynamicContent` and a text node. A numeric binding exclusively owns content; content steps on that node are rejected (`OVERLAPPING_WRITERS`).

## Sampling

`sampleScene` applies content steps like visible steps (hold until the next step on the same channel). After track sampling, for each text node with `numeric`:

1. `value = pose.textNumber ?? node.numeric.value` (the `text.number` track wins while active).
2. `content = resolveNumericContent(value, node.numeric.format)`.

A scene without numeric bindings or content steps samples exactly as in 0.17.0. `ResolvedFrame` text geometry carries the derived content string.

## Authoring gates assessment

1. **Simplicity.** Format lives on the text node; no separate binding table or calculator-level arithmetic.
2. **Generation.** Additive on existing text nodes and tracks.
3. **Streaming.** Number tracks and post-seal content steps recompute without rewriting sealed history.
4. **Expressiveness.** Formatting stays in `@gvr/schema` text-metrics; layout metrics and glyph animators remain separate capabilities.

## Readers

A 0.18 consumer accepts wire `"0.2"` documents. Migrated 0.1 scenes have no numeric bindings or content steps.

## Not in this release

Layout metrics / font readiness, per-glyph animators, wrapping, and adapter lowering from Lottie/SVG text animators.
