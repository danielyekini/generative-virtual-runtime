# Scene IR 0.15.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0 for a new capability contract. Documents still declare `irVersion` `"0.2"` and gate the new feature with `requiredCapabilities` containing `space.planarSeams` (with `space.planar25d`). A package that does not enable that capability rejects the scene at accept time; older validators reject the unknown `seams` key on a spatial layer.

## Capabilities introduced

- space.planarSeams

## Representation

Optional field `seams: SpatialSeamsDefinition` on `SpatialLayerDefinition`, wherever spatial layers appear (scene and `CREATE_SCENE` header; still a base definition frozen after the first seal).

- `SpatialSeamsDefinition`: `{ split?, edgeEpsilon?, maxFragments?, edges? }`. `split` is a boolean (default `true`). `edgeEpsilon` is finite and greater than 0 (default 0.001). `maxFragments` is an integer from 0 to 1024 (default 64). Unknown keys are rejected.
- `edges`: an array of `{ a, b }` naming two different surfaces of the same layer. A pair appears at most once, in either order. At most 1024 edges.

Validation: a present `seams` object requires `space.planarSeams`.

## Sampling

Frame sampling is unchanged. At frame resolution, projection with seams (`projectSpatialFrame`) replaces an intersecting surface's draw item with its clipped fragments in place. The `ResolvedFrame` draw list and render tree can then hold several items with the same `nodeId`. Fragments are path geometry with the surface's appearance. Ordering inside each compositing scope still follows plane tests. Layers without `seams` project exactly as in 0.14.0.

## Readers

A 0.15 consumer accepts wire `"0.2"` documents. Migrated 0.1 scenes have no spatial layers.

## Not in this release

Per-surface order channels, boolean union, near-plane clipping and spatial ops in `APPLY_ENTITY_PATCH`. Other pending ids remain outside this file.
