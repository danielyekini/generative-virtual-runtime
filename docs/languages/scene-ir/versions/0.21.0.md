# Scene IR 0.21.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0 for a new capability contract. Documents still declare `irVersion` `"0.2"` and gate dashed strokes with `requiredCapabilities` containing `paint.strokeDash`. A package that does not enable that capability keeps solid strokes. Decision: `docs/decisions/engine/path-progress-geometry-authoring.md` (E038).

## Capabilities introduced

- paint.strokeDash

## Representation

`Stroke` gains optional `dash` (positive finite lengths in local geometry units) and `phase` (pattern offset in those units). Phase requires `dash`. Omitted phase means 0. Omitted dash means a solid stroke.

`NodeAnimChannel` gains `stroke.phase`. A track on that channel requires a dash on the target node.

## Sampling

A `stroke.phase` sample replaces `Stroke.phase` and leaves the dash array in place. Colour and width tracks are unchanged. Spatial projection scales `dash` lengths and `phase` by the same area factor as `stroke.width`.

The canvas renderer calls `setLineDash` with the sampled dash and sets `lineDashOffset` to the sampled phase, including text strokes. A stroke without `dash` still clears the dash.

## Authoring gates assessment

1. **Simplicity.** The dash lives on the stroke. Sampling writes one number.
2. **Generation.** Additive fields on a stroke object that already exists. Scenes without them stay valid 0.20 documents.
3. **Streaming.** Phase is a scalar track. No per-frame geometry buffer.
4. **Expressiveness.** Paint dash is not trim and not the geometry `dashCommands` helper. Width profiles stay out.

## Readers

A 0.21 consumer accepts wire `"0.2"` documents. Migrated 0.1 scenes have no dash fields and stay solid. Older validators reject unknown `dash` and `phase` keys and the `stroke.phase` channel.

## Not in this release

Variable width profiles, dash-as-trim, and adapter lowering of foreign dash arrays.
