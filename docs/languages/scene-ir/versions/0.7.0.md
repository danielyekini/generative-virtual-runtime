# Scene IR 0.7.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0 for a new capability contract. Documents still declare `irVersion` `"0.2"` and gate the new feature with `requiredCapabilities` containing `entities.drawableBindings` (and `entities.durableRevisions` for `APPLY_ENTITY_PATCH`). A package that does not enable that capability rejects `REGISTER_GEOMETRY` / `BIND_GEOMETRY` at admission.

## Capabilities introduced

- entities.drawableBindings

## Representation

`EntityPatch` may include `REGISTER_GEOMETRY` and `BIND_GEOMETRY` alongside the 0.6.0 topology/ownership/behaviour ops. `REGISTER_GEOMETRY` publishes an immutable `GeometryAsset` (`id`, `space`, `node`); re-registering the same id fails. Geometry ids must not collide with entity ids. `BIND_GEOMETRY` attaches a present drawable entity to a known geometry at `activationMs >= sealedThroughMs`.

Sampling projects bound drawables by cloning the shared asset under the instance entity id (`resolveDrawable` / `projectScene`). Channel ownership and named behaviours remain exclusive per `(entityId, channel)` on the instance. Activation at or after the sealed horizon is allowed and remains invisible to the sealed left-limit sample; activation before the seal is rejected.

`composition.definitions` / `instances` remain authoring records that do not expand into draw lists; shared-geometry binding is the versioned reuse path.

## Readers

A 0.7 consumer accepts wire `"0.2"` documents. Drawable-binding ops require `entities.drawableBindings` in `requiredCapabilities`. Migrated 0.1 scenes do not gain bindings.

## Not in this release

Other pending ids remain outside this file. Adapter coverage is in the registry. Declarative MotionScript bind syntax remains E006.
