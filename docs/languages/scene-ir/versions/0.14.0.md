# Scene IR 0.14.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0 for a new capability contract. Documents still declare `irVersion` `"0.2"` and gate the new feature with `requiredCapabilities` containing `audio.generative` (and `audio.cues` when audio resources or cues are present). A package that does not enable that capability rejects generative sources at accept time.

## Capabilities introduced

- audio.generative

## Representation

Audio resources (still `kind: "audio"` on `resources`, carried on `CREATE_SCENE`) gain an optional tagged `source`:

- Href (0.11.0 form, still valid): `{ id, kind: "audio", href, durationMs, readiness? }` or `source: { type: "href", href }` with the same flat fields.
- Generative: `{ id, kind: "audio", source: { type: "generative", modality: "speech"|"effect", prompt, voice?, durationHintMs?, loop?, seed?, style? }, durationMs?, href?, readiness? }`.
  - `style` may carry `stability` / `similarity` / `speed` (finite numbers).
  - No vendor endpoint, model id, or API key fields.
  - `durationMs` may be provisional or omitted while `readiness` is `pending`; a `ready` generative resource needs positive `durationMs`. Hosts may fill `href` after materialisation.

Cues (`audioCues` / `ADD_AUDIO_CUES`) are unchanged from 0.11.0. Cue offset/duration checks against resource length apply when `durationMs` is known.

Validation: generative sources require `audio.generative`; any audio resource or cue still requires `audio.cues`.

## Sampling

Frame sampling is unchanged. Audio schedule / hold / export follow `AudioSession` with duration revision for generative resources.

## Readers

A 0.14 consumer accepts wire `"0.2"` documents. Migrated 0.1 scenes have no audio. Older 0.2 readers that lack `audio.generative` reject generative sources.

## Not in this release

Provider packages, Studio credential UX, music generation, and alignment tracks. Other pending ids remain outside this file.
