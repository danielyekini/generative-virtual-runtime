# Scene IR 0.13.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0 for a new capability contract. Documents still declare `irVersion` `"0.2"` and gate the new feature with `requiredCapabilities` containing `physics.planar2d`. A package that does not enable that capability rejects the scene at accept time; older validators reject the unknown `physics` key.

## Capabilities introduced

- physics.planar2d

## Representation

Optional scene field `physics: PhysicsWorldDefinition`, also allowed on the `CREATE_SCENE` header (it is a base definition, frozen after the first seal). It aligns with the `@gvr/runtime` `PhysicsSession` / authored-constraint profile.

- `PhysicsWorldDefinition`: `{ id, mode, gravity?, fixedDtMs?, seed?, maxBodies?, maxJoints?, maxContactsPerStep?, maxSolverIterations?, maxStepsPerAdvance?, bodies, joints?, constraints? }`. `mode` is `"dynamic"` or `"authored"`. At most one world per scene. Body count ≤ 256; joint count ≤ 256.
- `PhysicsBodyDefinition`: `{ id, entityId?, kind, x, y, angle, vx?, vy?, omega?, mass?, restitution?, friction?, collider, surfaceId? }`. `kind` is `static|kinematic|dynamic`. `collider` is `{ kind: "circle", radius }` or `{ kind: "aabb", halfWidth, halfHeight }` with positive extents. `entityId` defaults to `id` and must name a root-scene node.
- `PhysicsJointDefinition`: `{ id, bodyA, bodyB, restLength, anchorA?, anchorB?, compliance? }` with body ids from the same world and `compliance` in `[0, 1]` when present.
- `PhysicsConstraintDefinition`: `{ id, a, b, restLength, stiffness? }` for authored mode; `a`/`b` name root-scene nodes; `stiffness` in `[0, 1]` when present.
- Dynamic mode requires at least one body; authored mode requires at least one constraint and rejects joints.
- Owned channels: each body entity exclusively owns `transform.position.x`, `transform.position.y`, `transform.rotation`. Authored constraint endpoints exclusively own position.x/y. Timeline tracks and interaction bindings that write the same scalars are rejected (`OVERLAPPING_WRITERS`).

Validation: a present `physics` object requires `physics.planar2d`.

## Sampling

Frame sampling and `ResolvedFrame` are unchanged. A host advances the world with `createScenePhysicsSession` and applies writes as a `SampleOverlay` (or equivalent) before paint. A scene without `physics` samples exactly as in 0.12.0.

## Readers

A 0.13 consumer accepts wire `"0.2"` documents. Migrated 0.1 scenes have no physics world.

## Not in this release

Volumetric 3D rigid bodies, soft bodies, fluids, motors, CCD, and physics ops in `APPLY_ENTITY_PATCH`. Other pending ids remain outside this file.
