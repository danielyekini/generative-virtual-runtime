# MotionScript 0.24.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0 for new syntax and semantics. Scene IR moves to 0.23.0
with it, because cyclic scopes change the validated representation and the
sampling rules. Programs still declare `version "0.2"`. The compiler adds
`requires "timing.cyclicScopes"` (beside `timing.localScopes`) whenever a
`timing` declares a `period`. Decision:
`docs/decisions/engine/time-composition.md` (E014, implemented by E043).

## Capabilities introduced

- timing.cyclicScopes

## Syntax

```
timing swing { period 2s; };
timing lead { offset 1s; period 2s; };
timing blink { offset 1s; period 500ms; repeat 4; };
keyframes Lead.position.x {
  timing lead;
  at 0s 120 ease easeInOut;
  at 1s 520 ease easeInOut;
  at 2s 120;
};
step Lamp.visible { at 0ms; value true; timing blink; };
step Lamp.visible { at 250ms; value false; timing blink; };
seal 2s;
```

- **`period <duration>;`** inside `timing` makes the scope cyclic. The period is
  a positive length. It does not take a beat.
- **`repeat <n>;`** makes it a finite repetition of `n` cycles, an integer from
  1 to 10 000. `repeat` without `period` is rejected. With no `repeat`, the
  cycle is unbounded.
- **`timing <scope>;`** may follow `value` in a `step`. The scope chain must
  contain a period. The step's `at` is then cycle-local.
- `period` and `repeat` match by spelling inside a `timing` block. They are
  **not** reserved words, so nodes named `period` or `repeat` keep compiling.
- `offset`, `stretch` and `parent` keep their 0.2 meaning. Combined with a
  period, the offset is the cycle's **phase**.

## Semantics

Sampling follows Scene IR 0.23.0:

- **Unbounded cycle.** Local time is `wrap((parent − offset) / stretch, period)`.
  This is non-negative on both sides of the offset, so a segment can run
  through the scene seam.
- **Finite repeat.** The scope is not entered before its first cycle, wraps for
  `n` periods, and is then pinned at the period. The last cycle's
  `fill forwards` holds apply afterwards.
- Cycles are half-open. Rotation stays unwrapped degrees, so a 0 → 360 spin per
  period has an exact seam.
- `local_t` and `progress` in expressions follow the cyclic local time. `t`
  stays absolute scene time.

The compiler rejects:

- a track or step that does not lie inside one period of its innermost cycle;
- a step that names an affine-only scope;
- a second writer on a channel that a cyclic chain owns (`OVERLAPPING_WRITERS`).

**Streaming.** A writer may join a cyclic chain only while the seal has not
reached the chain's entry. For an unbounded cycle the entry is −∞, so every
writer of that cycle must arrive before the first seal. Late writers are
`INVALID_TIMING`, and the stream linter reports them as
`SEALED_HISTORY_WRITE`. Send a loop's complete cycle as one dependency-complete
group, then seal.

Programs that never write `period` compile byte-for-byte as in 0.23.0, with no
new capability.

## Authoring gates assessment

1. **Simplicity.** A route is written once in seconds with named eases, plus
   one `period` and an `offset` phase. The `t % P` ramps, clamps and seam
   derivatives go away. City's 442-character van expression becomes nine timed
   keys.
2. **Generation.** Two spelled words on an existing block and one optional line
   on `step`. No new reserved words and no control flow.
3. **Streaming.** A cycle is complete before its first sealed instant, and its
   ownership is exclusive. A sealed prefix is never reinterpreted.
4. **Expressiveness.** Bounded repetition of time. Finite repetition and loops
   are distinct and both bounded. The modulo is computed by the runtime.

## Not in this release

- composition instances on cyclic scopes;
- loops, functions or timers;
- a scene-level loop flag (that is host playback);
- periods that change over time;
- shortest-arc rotation;
- velocity-facing.
