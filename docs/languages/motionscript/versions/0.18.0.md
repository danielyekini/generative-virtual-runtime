# MotionScript 0.18.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0 for a new capability contract. Programs still declare `version "0.2"` and gate the new feature with `requires "text.dynamicContent"` (the compiler adds it when a text `number` binding, format field, content step, or `number` track is present). A package that does not enable that capability rejects the document at accept time. Decision: `docs/decisions/engine/dynamic-text-and-metrics.md` (E013); landed by E040.

## Capabilities introduced

- text.dynamicContent

## Syntax

No new reserved words. Format and number fields match by spelling inside a `text` body. `content` steps reuse the existing `step` production with a string value.

```
text Price {
  content "0.00";
  fontSize 28;
  fill #22c55e;
  align center;
  number 42.5;          // base numeric value
  fractionDigits 2;
  group ",";
  prefix "$";
};
animate Price.number { from 10; to 99.5; duration 3s; };

text Status {
  content "Ready";
  fontSize 18;
  fill #f8fafc;
};
step Status.content { at 1s; value "Set"; };
step Status.content { at 2s; value "Go"; };
```

- `number` on a text node enables a numeric format binding. Optional format fields: `fractionDigits`, `minIntegerDigits`, `sign` (`auto` | `always` | `never`), `group`, `decimal`, `prefix`, `suffix`. Format fields without `number` are rejected.
- `Price.number` is a new number channel. It is legal only on a text node that has a numeric binding; the track overrides the binding's base `value` while active.
- `step Label.content { at t; value "…"; }` writes discrete single-line string content. Continuous string interpolation is not offered. Content steps require a text node and cannot share a node with a numeric binding (`OVERLAPPING_WRITERS`).

## Semantics

Sampling derives display content for a numeric binding with `resolveNumericContent(sampledNumber, format)` from `@gvr/schema` (same half-away-from-zero rules as the E013 prototype). Discrete content steps hold until the next content step on that node. The authored `content` string remains the pre-sample fallback for tools that do not sample, and the base before the first content step.

Ownership: a numeric binding exclusively owns content on its node. Timeline content steps on that node are rejected. Sealed generative tracks are not rewritten; late content updates use steps after seal or number tracks on the binding.

## Authoring gates assessment

1. **Simplicity.** One text node plus `fractionDigits 2` (and friends) replaces N static content variants and opacity choreography. Authors never compute glyph tables for this slice.
2. **Generation.** Additive on existing `text.basic`: models that already emit numbers and labels add `number` / format fields or a content step. No new reserved words.
3. **Streaming.** Derived content recomputes from the sampled number; discrete content updates are explicit steps, not sealed-prefix rewrites.
4. **Expressiveness.** Rounding, padding and units live in the format helper; per-glyph / `text.animators` and layout metrics (`text.layoutMetrics`) stay outside this release.

## Readers

A 0.18 consumer accepts wire `"0.2"` documents. Numeric bindings and content steps require `text.dynamicContent` in `requires`; the compiler adds it. Older packages reject the capability token, the unknown `numeric` key on text nodes, the `text.number` / `content` channels, and content steps. Programs without dynamic text compile exactly as in 0.17.0.

## Not in this release

`text.layoutMetrics` (E041), `text.animators`, wrapping / multi-line, continuous string morphing, and Lottie text-animator import.
