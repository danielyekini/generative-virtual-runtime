# MotionScript 0.13.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0 for a new capability contract. Programs still declare `version "0.2"` and gate the new feature with `requires "physics.planar2d"` (the compiler adds it when a `physics` declaration lowers). A package that does not enable that capability rejects the document at accept time. Decision: `docs/decisions/engine/physics-integration.md` (E011); versioning E029.

## Capabilities introduced

- physics.planar2d

## Syntax

`physics` is the only new reserved word. `mode`, `body`, `joint`, `constraint`, `entity`, `kind`, `collider`, `gravity` and every other body word are matched by spelling and stay usable as identifiers elsewhere.

```
physics bowl {
  mode dynamic;
  gravity (0, 980);
  fixedDtMs 16.666666666666668;
  seed 1;
  body marble {
    entity Marble;
    kind dynamic;
    position (120, 40);
    mass 1;
    restitution 0.35;
    friction 0.2;
    collider circle 14;
  };
  body floor {
    entity Floor;
    kind static;
    position (200, 280);
    collider aabb 180 10;
  };
  joint link {
    a marble;
    b floor;
    restLength 200;
    compliance 0.2;
  };
};
```

Authored (non-dynamic) profile:

```
physics rods {
  mode authored;
  constraint rod {
    a A;
    b B;
    restLength 40;
    stiffness 1;
  };
};
```

- `physics <id> { … };` declares the scene's single planar physics world. A second world is rejected.
- World: `mode dynamic|authored;` (required), optional `gravity (x, y);`, `fixedDtMs`, `seed`, and solver limits (`maxBodies`, `maxJoints`, `maxContactsPerStep`, `maxSolverIterations`, `maxStepsPerAdvance`).
- `body <id> { … };` (dynamic): `kind static|kinematic|dynamic;` (required), `collider circle <r>;` or `collider aabb <hx> <hy>;` (required), optional `entity` (defaults to body id), `position`, `angle` (radians or angle token), `velocity`, `omega`, `mass`, `restitution`, `friction`, `surface`.
- `joint <id> { a <body>; b <body>; restLength n; … };` distance joints between bodies of the same world.
- `constraint <id> { a <entity>; b <entity>; restLength n; … };` authored position-based rods (authored mode).
- A dynamic world needs at least one body; an authored world needs at least one constraint. Body/constraint entities may precede their nodes; unresolved ids report `UNKNOWN_TARGET`. The world is a base definition: frozen after the first `seal`.
- Physics exclusively owns `transform.position.x`, `transform.position.y` and `transform.rotation` for each body entity (authored constraints own the endpoints' position channels). Tracks and input bindings that write the same scalars are rejected.

## Semantics

Fixed-step integration, ownership writes, drag handoff, checkpoints and authored constraint solving follow the E011 decision and the `@gvr/runtime` `PhysicsSession` / `createScenePhysicsSession` contract. This release defines the syntax, the Scene IR it lowers to and the validation bounds.

## Readers

A 0.13 consumer accepts wire `"0.2"` documents. Physics requires `physics.planar2d` in `requires`. Older packages reject `physics` as an unexpected declaration. Programs without it compile exactly as in 0.12.0, including identifiers spelled like physics body words.

## Not in this release

Volumetric 3D rigid bodies, soft bodies, fluids, motors, continuous collision detection, velocity/readback channels as track targets, and Studio inspector UI. Other pending ids remain outside this file.
