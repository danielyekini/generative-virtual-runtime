# MotionScript 0.8.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0 for a new capability contract. Programs still declare `version "0.2"` and gate the new feature with `requires "paint.animatedSolid"`. A package that does not enable that capability rejects the document at accept time. A 0.7.0 package without the capability does not accept animated solid paint tracks.

## Capabilities introduced

- paint.animatedSolid

## Syntax

Nodes with solid fill or stroke may animate component channels:

```
keyframes Dot.fill.r {
  start 0ms;
  duration 1000ms;
  0% 1;
  100% 0;
};
keyframes Dot.fill.a {
  start 0ms;
  duration 1000ms;
  0% 1;
  100% 0.25;
};
keyframes Ring.stroke.width {
  start 0ms;
  duration 1000ms;
  0% 2;
  100% 8;
};
```

`fill.r`, `fill.g`, `fill.b`, `fill.a`, `stroke.r`, `stroke.g`, `stroke.b`, and `stroke.a` are straight-alpha components in `[0, 1]`. `stroke.width` is a positive local width. Static fill/stroke declarations remain the authored base; tracks override sampled values. Node `opacity` stays independent of paint alpha. Gradients and non-uniform stroke width are unchanged and outside this capability.

## Readers

A 0.8 consumer accepts wire `"0.2"` documents. Animated solid paint requires `paint.animatedSolid` in `requires`. There is no lossless down-conversion that expands paint tracks into overlay node copies for older readers.

## Not in this release

Other pending ids remain outside this file. Adapter coverage is in the registry. Whole-colour track value types and gradient-stop animation remain open.
