# MotionScript 0.23.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0 for new syntax. **MotionScript only:** Scene IR stays at
0.22.0, because timed keys and beats lower onto the track `startMs`,
`durationMs` and keyframe offsets that Scene IR already stores. Programs still
declare `version "0.2"`. No `requires` token is added, and the emitter writes
the percentage form. Decision: `docs/decisions/engine/time-composition.md`
(E014, implemented by E044).

## Capabilities introduced

- timing.timedKeys

## Syntax

```
beat intro at 0s;
beat cross at intro + 1.5s;
beat settle at cross + 2s;
keyframes Ball.position.x {
  fill forwards;
  at intro 80 ease easeInOut;
  at cross 320 ease easeOut;
  at settle - 0.5s 540;
};
animate Caption.opacity { from 0; to 1; start cross; duration 400ms; fill forwards; };
step Caption.visible { at settle; value false; };
seal settle;
```

- **Timed keys.** `at <time> <value> [ease …] [spatial …];` inside `keyframes`.
  The track starts at the first key and lasts until the last key. The compiler
  lowers keys to offsets with exact quotients. At least two keys are required,
  and times strictly increase. `start` and `duration` headers are rejected with
  timed keys. A track uses percentage keys or timed keys, not both.
  Percentage keys stay valid. Key times are in the track's own time domain, so
  they are scope-local under `timing`.
- **Named beats.** `beat <name> at <time>;` or `beat <name> at <beat> ± <time>;`
  declares a compile-time constant time. A reference names an earlier beat.
  Forward references, duplicate names and results that are negative or not
  finite are rejected. Beats may be declared after a seal. They cannot appear
  inside a `batch`. MotionScript 0.1 programs reject beats and timed keys.
- **Where a beat may appear.** Time positions written with the grammar's
  `duration` production: `animate` / `keyframes` `start`, timed key `at`,
  `step` `at`, `seal`, `timing` `offset` and `cue` `at`. Each takes `<beat>`,
  `<beat> + <time>` or `<beat> - <time>`. Lengths (`duration`, cue `offset`,
  `duration`, `fadeIn`, `fadeOut`) never name a beat: a beat is a point in time.
  To end a track at a beat, use timed keys.
- `beat` is matched by spelling at the start of a unit. It is **not** a reserved
  word, so nodes and other identifiers named `beat` keep compiling. Beat names
  are identifiers, so a keyword such as `at` cannot be a beat name.
- After a beat name, `+` or `-` followed by a duration is the offset. Any other
  sign belongs to the key value, so `at b -5;` is the value −5 at beat `b`.

## Semantics

A beat binds when its unit is pushed, before any deferral. A track that waits
for a later node therefore cannot read a beat that is declared after it.
A beat that a streamed unit has read never changes.

Beats do not create scopes. A beat-local track uses an ordinary affine
`timing` scope whose offset is the beat, and its keys are scope-local.

Per-beat `animate` / `keyframes` blocks follow the gap/hold rule that E014
pinned. Writers use half-open intervals, so the later track owns a shared
boundary. In a gap, the latest-ended `fill forwards` writer holds; otherwise
the authored base value applies. There is no backwards fill.

## Authoring gates assessment

1. **Simplicity.** Authors write `at 4.4s` or `at cross + 0.4s`. They no longer
   convert each beat to a percentage of a full-length track (MotionScript →
   Motion used 647 such literals, From Pixels to Prediction used 1,386).
   Moving one beat moves every key that names it.
2. **Generation.** Named beats give models a stable vocabulary for story
   moments. Models do not re-derive every ramp when a beat moves.
3. **Streaming.** Beats are declared before use and never change, so a sealed
   unit's times are final. A beat adds nothing to Scene IR and no delta.
4. **Expressiveness.** Division into offsets happens in the compiler. Tracks
   keep their own interval, ease and fill.

## Readers

A 0.23 compiler accepts every 0.22 program unchanged. Older compilers reject
`beat` units and `at` keys as syntax errors. Compiled Scene IR is readable by
any 0.22 runtime, because no Scene IR field, op or capability token changed.

## Not in this release

Cyclic scopes (`period`, `repeat`; E043 `timing.cyclicScopes`), beats on
lengths, and loops or timers.
