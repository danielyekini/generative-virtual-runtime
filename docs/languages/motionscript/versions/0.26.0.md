# MotionScript 0.26.0

Published. Do not edit. Wire version `"0.2"`.

Minor bump below 1.0. Forbids the inert `timing` property on composition
`instance` records. Scene IR moves to 0.25.0 with it. Programs still declare
`version "0.2"`. No new capability token — this removes a diagnostic lie
(E048 / E050). Decision: `docs/decisions/engine/composition-instance-timing.md`.

## Capabilities introduced

None. `composition.definitions` restrictions note the forbid.

## Syntax

```
instance one of chip {
  start 0ms;
  end 1s;
  // timing local;  // rejected: UNSUPPORTED_PROPERTY
};
```

- `timing <scope>;` inside an `instance` body is still lexed so the compiler
  can emit `UNSUPPORTED_PROPERTY` instead of a bare parse failure.
- Tracks, steps and `timing` scope declarations are unchanged.

## Semantics

- Composition instances remain non-drawing records. They never sampled a
  timing scope; removing the property does not change frames.
- Per-instance phase on drawn motifs stays with drawable bindings and cyclic
  scopes on real entity ids.

## Language change gate

- **Authoring simplicity:** authors stop inventing a required timing line that
  never moved anything.
- **Generation friendliness:** models lose a brittle required property on a
  non-drawing record.
- **Streaming:** unchanged — instances stay frozen base records.
- **Expressiveness vs computation:** retiming shared motifs uses bindings and
  cyclic scopes, not composition records.

## Out of scope

Composition playback / drawn instances with local time (needs a new decision).
Lottie precomp timing as a native backlog.
