# Final intent review

## Intended system

Continuous user conversation produces expressive answers and persistent interactive programs. Director receives only its system prompt and conversation history, speaks directly to the user using JSON as its response language, and selects an inferred experience. GVR obtains runtime state for implementation updates. Richness comes from design and natural-language direction, not mandatory schema detail. Timing is useful locally and must never become a blanket duration requirement. Structural work should favour dimensional assembly/cutaway and direct manipulation while preserving orthographic inspection. Taste should generalize beyond a single house.

## Experiment findings

1. Initial rich 0.2 sales landing page: strong composition and shared-lead identity, but roughly 26.8 KB for four beats. Default 30 seconds turned a website request into a presentation. Repeated states, holds and synchronization inflated output; initial visibility conflicted with reveal actions. Diagnosis: schema burden and experience framing. No controlled latency benchmark.
2. Early 0.3 house follow-up: director emitted stateRequest despite adequate conversational intent. Diagnosis: leaked runtime-ID responsibility. Subsequent 0.4 explicitly removes this boundary error.
3. Compact 0.4 house/island conversation: appropriate semantic updates and reduced output for local edits. All turns chose immediate presentation, missing preferred assembly/overview. Sink wording inferred unseen geometry. Later skill edits address proportional motion, semantic spatial relations, implicit preservation and incremental assumptions.
4. Mathematics workspace: appropriate diagnostic, cautious learning-map evidence, correct algebra correction and optional visual walkthrough. The visual model for adding units to x−2 was underspecified; response disclosed the entire answer before the sequence; learner-paced progression and conversational event handoff were not explicit. These remain research items rather than proven renderer failures.
5. Single-storey implementation: navy top-down immediate design followed the director. Zero tracks were consistent with immediate presentation. Supplied retrospective reports working bounded controls but absent/unverified pinch/wheel gestures, partial drag coverage, failed mobile reflow and missing easy in-surface assumption edits. These are end-to-end gaps, not evidence that a style gate rejected dimensional output.
6. Spatial retry and raised-wall follow-up: director expresses dimensional preference and richer controls. Supplied artifacts and retrospectives require verification against each promise; no fresh render was performed here. The raised-wall historical context paired a two-storey director response with a single-storey base. Corrected transcript provenance retains that mismatch separately. This is a context-integrity failure, not something to repair by inventing an intermediate turn.

## Remaining intent loss

The strongest unresolved boundary is that the director's textual answer can diverge from the actual program. Future turns must not treat unimplemented promises as existing facts. Keep implementation outcomes outside director technical context; test a concise user-facing semantic outcome in conversation history, with no IDs/source/geometry dumps, before adoption. This is a proposed refinement of history handling, not an implemented host path.

The long skill is more flexible than the original schema but includes growing example-specific guidance. Measure its effect rather than accumulating every failure as another permanent paragraph. Keep taste preferences and interaction conventions identifiable and test them across domains.

A director's precise prose cannot supply missing responsive lifecycle, input or spatial capabilities. Prompt quality and runtime capability need separate evaluations. Do not silently downgrade controls or claim finished rendering from successful compilation.
